# 第一阶段浏览器验收

在 Windows 桌面 Chrome 或 Edge 运行 `npm run test:browser`。浏览器脚本使用独立配置和随机回环端口，不使用日常购物数据。

在 Android Chrome 和 iPhone Safari 使用一次性 HTTPS 测试地址，记录设备、系统版本、浏览器版本及结果。若测试地址包含本项目源码，可在仓库子路径打开 `tests/browser.html` 跑同一套浏览器断言。正式构建不包含测试文件。以下人工步骤同时覆盖真实系统文件选择、下载和后台切换。

| 用例 | 操作与期望 |
| --- | --- |
| 数量未知 | 手工添加「盐」，数量和单位留空。导出后检查 `quantity: null`。 |
| 结构校验 | 粘贴包含土豆 4 个、土豆 300 克、新鲜番茄 2 个、番茄罐头、三文鱼和可选葡萄的有效 JSON。显示预览；两条土豆应提示同名并保持不同单位，新鲜和罐头番茄保持独立。另试负数、未知商店和版本 2，均显示错误。 |
| 商店约束 | 醋设仅限 99 Ranch Market，牛奶设优先 99 Ranch Market。H-E-B 默认不显示醋和牛奶。开启跨店后可加入牛奶，醋仍须改规则。切到 99 Ranch Market，醋出现在候选，确认前购物区无该商品。 |
| 刷新与后台 | 把醋和葡萄加入 99 Ranch Market，勾选醋。刷新，切到另一个应用再回来，醋仍勾选。取消勾选后再勾选一次。 |
| 结束与复购 | 关闭行程，未购葡萄回待购池且保留可选标记，已购醋进入历史。再次打开同店行程，醋不会成为待购候选。 |
| 重复导入 | 同一 JSON 调换字段或条目顺序后再次粘贴。预览提示已导入，默认不能提交。明确确认后可新增购买需求，历史记录保留。 |
| 文件与恢复 | 选择文件方式导入一批商品。下载完整备份。清空测试来源的站点数据并重新打开，选择备份文件。未勾选覆盖确认时不能恢复，勾选后取消浏览器确认也不写入。完成两次确认后对比两份备份，除了 `exportedAt` 应相同，原批次仍会被识别。 |
| 界面与发布 | 竖屏滚动，操作主要按钮，确认无横向溢出。刷新 GitHub Pages 仓库子路径，确认资源可加载。正式发布目录中应只有静态站点资源。 |

第二阶段另验文字解析的原文保留与可编辑预览，以及首次联网缓存后断网启动、勾选、关闭再打开和升级数据保留。
